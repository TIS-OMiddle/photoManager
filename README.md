这是一个照片管理工具，主要工作是接收一个照片目录，然后根据照片的元数据（如日期、时间、地点等）进行分类和管理。


技术栈是go，需要安装其他必要的库。

目前只提供基本CLI版本，实际逻辑函数应该独立实现，接收一个参数结构体并返回必要信息，以支持后续的UI化可能（直接调用核心逻辑函数）。

主要参数设计功能有：
1. 源路径。即图片目录，支持传入额外选项判断是否递归处理子目录。
2. 目标路径。即分类后的图片目录。
3. 整理后的目录结构字符串。支持用户自定义目录结构，如"{yyyy}-{MM}-{dd}"、"{yyyy}-{MM}-{dd}/{HH}-{mm}-{ss}"等,其中"{}"里面的变量会被替换为实际的日期、时间等，"/"表示目录分割。
4. 文件处理方式，3个选项：
   a. "dry-run": 仅模拟处理，不实际移动或删除文件，用于测试。最终应当输出所有拟移动的文件路径。
   b. "copy": 复制文件到目标目录。
   c. "move": 移动文件到目标目录。
5. 照片“时间信息”获取，用于适配步骤3中的目录结构字符串。可选项有以下
    a. "exif": 从照片的EXIF数据(拍摄时间)中获取时间信息。
    b. "create-time": 从文件的创建时间(如果支持)获取获取时间信息。
    c. "modify-time": 从文件的修改时间(如果支持)获取修改时间信息。
除此之外，你还应当支持用户自定义顺序，比如"exif"、"create-time"、"modify-time"等。如果没有获取到任何时间信息，跳过该文件处理并输出警告信息。
6. 目标路径存在同名文件时的处理策略，可选项有以下
   a. "overwrite": 覆盖已存在的文件。
   b. "skip": 跳过已存在的文件，不进行处理。
   c. "rename": 重命名已存在的文件，格式为"{filename}_{timestamp}.{ext}"。


cli输出信息要求：
如果是dry-run模式，那么最终应当输出所有拟移动的文件路径，而不是实际移动文件。
如果是copy模式，那么最终应当输出所有复制的文件路径。
如果是move模式，那么最终应当输出所有移动的文件路径。
其他警告信息。
不要打印大量无效信息告知用户，只打印必要的信息。
最后打印“成功/总数”的信息，比如 "已处理 8/8，耗时 2.5s" 或者 "已处理 4/8，耗时 1.5s"。


性能要求：
建议4线程执行，单线程效率太低，建议使用多线程并行处理，以提高处理速度。
文件读写操作会是最耗时的部分，这个工具需要处理上万个文件，你做好各类缓存、减少文件操作次数、仅读取必要信息，以提高效率。
